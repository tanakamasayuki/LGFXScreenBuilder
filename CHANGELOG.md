# Changelog / 変更履歴

## Unreleased
- (EN) Add an embedded-font generator (§8.7.7). Rasterize a web font or your own typeface at a chosen size for a chosen character set and get a `lgfx::U8g2font` header — 1bpp, in flash, no runtime loading, drawn with `setFont(&MyFont)`. Available two ways from one pipeline: a standalone page (`docs/fontgen.html`) that just downloads a `.h` and needs no project, and Fonts mode in the editor, where the font is adopted onto the project and emitted into the exported header under the same per-profile flash policy as preset fonts.
- (JA) 埋め込みフォント生成機能を追加（§8.7.7）。Web フォントや手持ちの書体を、指定したサイズ・指定した文字種でラスタライズし、`lgfx::U8g2font` のヘッダとして出力する。1bpp・フラッシュ常駐・実行時ロード不要で、`setFont(&MyFont)` で描ける。使い方は 1 つのパイプラインで 2 通り: プロジェクト不要で `.h` をダウンロードするだけの単独ページ（`docs/fontgen.html`）と、エディタの Fonts モード（プロジェクトに採用し、プリセットフォントと同じプロファイル単位のフラッシュ方針で出力ヘッダに埋め込む）。
- (EN) Character sets are composed on independent axes (Latin/European, kana, han, hangul, symbols) rather than picked from a menu of bundles, and every set is derived from Unicode's own data — Unihan `kJoyoKanji` / `kJinmeiyoKanji` / `kJis0` / `kGB0` / `kBigFive` / `kKoreanEducationHanja` plus `KSC5601.TXT` — so sizes match the published standards exactly. Han is chosen **per language** and unioned, because Japanese, Simplified, Traditional and Korean are different repertoires rather than points on one scale. Tiers are cumulative unions, so moving up a level can never silently drop a character. Additive sets render as checkboxes and tiers as ladders, and one-click templates (Clock, Sensor readout, Japanese UI, …) fill in a starting selection that stays editable.
- (JA) 文字種は「詰め合わせのメニューから選ぶ」のをやめ、独立した軸（ラテン・欧文／かな／漢字／ハングル／記号）で組み立てる方式にした。すべてのセットは Unicode 自身のデータ（Unihan の `kJoyoKanji` / `kJinmeiyoKanji` / `kJis0` / `kGB0` / `kBigFive` / `kKoreanEducationHanja` と `KSC5601.TXT`）から導出しており、字数は公表された規格値と完全に一致する。漢字は**言語ごとに**選んで和集合を取る。日本語・簡体・繁体・韓国語は 1 本の尺度上の点ではなく別のレパートリーだからである。段階は累積和集合なので、段階を上げて文字が黙って消えることが原理的に起きない。加算されるセットはチェックボックス、段階はラダーで表示し、テンプレート（時計／センサー表示／日本語UI …）が 1 クリックで選択を埋める（あとから編集可）。
- (EN) Fixed two problems that made a filled-in font come out at the wrong scale. Whitespace was accepted without any check, so a font that lacks the ideographic space took its advance from a fallback at that font's own em — Micro 5 at a 32px character height gave U+3000 a 71px advance next to 34px kana, and that alone pushed the font past the format's advance limit. Its advance is now capped at the widest character. Separately, a fallback was scaled by whichever leftover character happened to be measured, because the reference character's subset was not among the ones fetched for it; the reference is now requested explicitly, and if the family genuinely lacks it the primary's em is matched instead.
- (JA) 補完したフォントの大きさがずれる問題を 2 つ修正した。空白文字が無検査で通っていたため、全角スペースを持たない書体ではフォールバックの em がそのまま送り幅になっていた（Micro 5 の文字高さ 32px で U+3000 が 71px、かなは 34px）。これだけで形式の送り幅上限を超えてもいた。送り幅は最も広い文字を上限とするようにした。また補完フォントが、残り文字の中から偶然選ばれた字を基準にスケールされていた（基準字のサブセットが取得対象に入っていなかったため）。基準字を明示的に要求し、その書体が本当に持たない場合は主フォントの em に合わせるようにした。
- (EN) A character that looks absent from a typeface is now asked again at a different size before being reported missing. The presence test decides by whether the rendering matches what the generic fallback draws, and that is wrong whenever the two match by coincidence: Noto Sans KR unquestionably has 굡, but at a 43.8px em it thresholded to exactly the same pixels and advance as both generics and was dropped, while the other 2,349 hangul of the same set came through — and at 32.9, 38.4, 49.3 and 54.8px it is found. A genuine absence matches at every size; a collision does not survive being re-rolled. The retry is skipped when none of the family's loaded faces declares the codepoint, so a Latin face asked for 2,350 hangul pays nothing for it.
- (JA) その書体に無いように見えた文字を、非収録と報告する前に別のサイズでもう一度判定するようにした。収録判定は「総称フォールバックが描いた結果と一致するか」で決めているため、偶然一致した場合に誤る。Noto Sans KR は `굡` を確かに持つが、em 43.8px では両方の総称と送り幅までピクセル単位で一致して落とされていた（同じ文字集合の残り 2,349 字は正常で、32.9 / 38.4 / 49.3 / 54.8px では検出される）。本当に無ければどのサイズでも一致するので、振り直せば偶然は残らない。読み込み済みフェイスがそのコードポイントを宣言していない場合は再判定を省くため、ハングル 2,350 字を求められたラテン書体に追加コストはかからない。
- (EN) Fixed a fallback that stopped part-way down the chain. The survey of which typefaces could fill a gap was used to *replace* the fallback chain, but a survey describes one gap and the gap moves when the character set changes — which, unlike a typeface change, does not clear the fallback. With the fallback already on, switching to the Korean set kept a plan of [Noto Sans, Noto Sans JP] and reported 2,350 hangul as absent from the typeface, while Noto Sans KR further down the chain — which has every one of them — was never asked. The survey now orders the chain instead of replacing it, so it can only make the answer arrive sooner, never make it smaller.
- (JA) 補完がチェーンの途中で止まる不具合を修正した。「どの書体が穴を埋められるか」の調査結果を、フォールバックチェーンの*置き換え*に使っていた。しかし調査が表すのはその時点の欠落であり、文字種を変えれば欠落は変わる——そして書体変更と違い、文字種変更ではフォールバック設定が解除されない。このため補完を有効にしたまま韓国語の文字セットに切り替えると、[Noto Sans, Noto Sans JP] という古い調査結果がそのまま使われ、ハングル 2,350 字が「この書体に無い」と報告された。その全てを持つ Noto Sans KR は、チェーンの先にいながら一度も問い合わせられていなかった。調査結果はチェーンの順序付けにのみ使うようにしたので、結果が早く出ることはあっても、収録が減ることはなくなった。
- (EN) A fallback family that fails to load no longer fails silently: the reason is kept on the result and logged, which is how a one-line bug that disabled fallback entirely was found in seconds rather than by bisection.
- (JA) 補完フォントの読み込み失敗を握りつぶさず、理由を結果に残してログにも出すようにした。おかげで補完が丸ごと効かなくなる 1 行のバグを、切り分けではなく即座に特定できた。
- (EN) A fallback choice is dropped when the typeface, weight or style changes — it was a decision about one font's gaps — and while it is on it stays visible and can be changed or turned off, which previously was impossible without reloading.
- (JA) 補完の設定は、書体・ウェイト・スタイルを変えたときに破棄するようにした（ある 1 つの書体の穴についての判断だったため）。また有効な間は常に表示し、変更も解除もできるようにした。従来はページを読み込み直す以外に戻す手段がなかった。
- (EN) Glyph width and height now use the full 8 unsigned bits the u8g2 decoder supports (255 rather than 127), which is what lets a large font encode at all. Bearings and the advance stay at 7 signed bits because LovyanGFX's decoder casts them through `int_fast8_t`; a font that exceeds that is refused with an error naming the character, the limit and the largest character height that would fit, instead of a bare "too large for this format".
- (JA) グリフの幅と高さを、u8g2 デコーダが対応する符号なし 8bit いっぱいまで使うようにした（127→255）。大きなフォントが符号化できるかどうかはここで決まる。ベアリングと文字送りは LovyanGFX のデコーダが `int_fast8_t` を経由するため符号付き 7bit のまま。これを超えるフォントは、単に「形式に対して大きすぎる」ではなく、どの文字がどの上限に当たったかと収まる最大の文字高さを示して拒否する。
- (EN) Fixed glyph-presence detection, which decided whether a typeface really has a character by comparing it behind two generic fallbacks. That only distinguishes anything while the two generics resolve to different physical fonts, so the result depended on the machine's installed fonts: a Roboto font was credited with 41 CJK unit symbols it does not have and shipped their tofu, and the same build reported different missing characters locally and on CI. Presence is now decided by drawing with the font in the stack and again with it removed — if the two match, the fallback drew it.
- (JA) グリフ収録判定の不具合を修正。従来は 2 つの総称フォールバック背後での描画を比較していたが、これは 2 つの総称が別の物理フォントに解決される間しか判別できず、結果が環境のインストール済みフォントに依存していた。実際、Roboto のフォントが持ってもいない CJK 単位記号 41 文字を収録扱いにしてその豆腐を出力し、同じビルドがローカルと CI で異なる欠落文字を報告していた。判定を「その書体を入れて描いた結果」と「外して描いた結果」の比較に変更した（一致すればフォールバックが描いたということ）。
- (EN) Characters above U+FFFF are excluded from the curated character sets rather than reported: a uint16 glyph encoding can never address them, so carrying 𠮟 (U+20B9F) in 常用漢字 only warned every project that selected it about something it could do nothing about. Custom text and ranges still report them, since there the user can act.
- (JA) U+FFFF を超える文字は、報告するのではなく文字集合から除外するようにした。uint16 のグリフ参照では絶対に扱えないため、常用漢字に `𠮟`（U+20B9F）を残しておくと、選んだ全プロジェクトに手の打ちようがない警告を出すだけだった。自由入力の文字と範囲については引き続き報告する（そちらはユーザーが行動できる）。
- (EN) A character the chosen typeface has no glyph for can be **filled in from another typeface** instead of dropped — Google's Noto Sans JP carries no Greek at all, so a Japanese UI showing Ω for ohms would otherwise lose it. It is offered, never applied unasked: the gap is detected, the characters and the typeface that could supply them are named, and one click applies it (stored on the recipe, so exports rebuild the same font). Filled-in glyphs are measured on the same reference character as the primary so the sizes match, and the generated header carries one attribution block per typeface used, because the font is then a derived work of each of them.
- (JA) 選んだ書体にグリフが無い文字を、落とさず**別の書体から補完**できるようにした。Google の Noto Sans JP はギリシャ文字を 1 文字も持たないため、オームの Ω を出す日本語 UI は何もしなければそれを失う。勝手には適用せず提案する: 穴を検出し、対象の文字と補完できる書体を名指しし、1 クリックで適用する（選択はレシピに保存され、エクスポート時も同じフォントが再生成される）。補完されたグリフは主フォントと同じ基準字で測るのでサイズが揃い、生成ヘッダには使用した書体ごとの帰属ブロックが並ぶ。フォントがその全ての派生物になるためである。
- (EN) A live preview sits with the typeface and size controls — the two settings numbers cannot convey — and follows every change. It rasterizes only the sample string, so it stays instant regardless of the character-set size, and goes through the same rasterizer as the real run: those are the output pixels, shown 1:1 by default. Characters that will not reach the generated font are marked rather than skipped: red crossed box = this typeface has no such glyph, amber = outside the selected character set. Defaults are now **Noto Sans JP at 32px**, because at 1bpp CJK below roughly 24px loses the strokes that tell kanji apart.
- (EN) The size field is the **character height**, not the line box. Line boxes vary widely between families, so the same number used to give visibly different text in two typefaces; it is now pinned to the ink height of a reference character taken from the set being generated. The line box is derived from the glyphs actually produced, which makes it exactly tall enough — no clipping, and no padding rows paid for in flash.
- (JA) 書体とサイズ（数値では判断できない 2 つの設定）のすぐ隣にライブプレビューを置き、変更に即座に追従するようにした。ラスタライズするのはサンプル文字列だけなので文字種の規模によらず一瞬で、しかも本番と同じラスタライザを通る。近似ではなく出力そのもののピクセルを既定で等倍表示する。生成フォントに入らない文字は詰めずに印を付ける: 赤い×枠＝その書体にグリフが無い、橙色＝選択中の文字種の外。既定値は **Noto Sans JP・32px** に変更。1bpp では概ね 24px を下回ると漢字を見分ける画線が失われるため。
- (JA) サイズ欄は**行の高さではなく文字の高さ**にした。行ボックスは書体ごとの差が大きく、同じ数値でも見た目の大きさが揃わなかったため、生成対象の文字集合から選んだ基準字の実インク高さに合わせる。行ボックスは実際に生成されたグリフから導出するので、ちょうど足りる高さになり、クリップも余白ぶんのフラッシュ消費も起きない。
- (EN) Presets are inspectable, not just countable: a charset inspector lists the actual characters grouped by Unicode block (findable with Ctrl+F), scopeable to one preset at a time. After generating, the same view marks characters the typeface turned out not to have — struck through in place, so checking for a specific character is one glance. The generated header is shown in full, and when a set is large enough that the preview is cut, it says so rather than trailing off in an ellipsis.
- (JA) プリセットは文字数だけでなく中身を確認できる: 収録文字インスペクタが実際の文字を Unicode ブロック別に一覧表示し（Ctrl+F で検索可）、プリセット 1 つだけに絞ることもできる。生成後は同じビューが、その書体に無かった文字をその場で取り消し線で示すため、特定の文字が入ったかは一目で分かる。生成ヘッダも全文を表示し、大きすぎて切り詰める場合は「…」で終わらせず、その旨を明示する。
- (EN) A generated font is stored on the project as a **recipe** (typeface, size, characters) — never as glyph bytes. The data is rebuilt at export, so project files stay small and a shared project carries no redistributable copy of a typeface. Google fonts re-fetch automatically; a typeface supplied as a local file has to be supplied again, and the tool says so rather than exporting a header with the font missing.
- (JA) 生成フォントはプロジェクトに**レシピ**（書体・サイズ・文字種）として保存し、グリフデータは保存しない。データは出力時に再生成されるため、プロジェクトファイルは小さいままで、共有したプロジェクトが書体の再配布可能なコピーを抱え込むこともない。Google Fonts は自動で再取得され、ローカルファイルで与えた書体は再指定が必要になるが、フォントが欠けたヘッダを黙って出力せず、その旨を表示する。
- (EN) Curated web fonts are limited to SIL Open Font License 1.1 and Apache-2.0 families, which permit embedding the generated data in firmware. Local files are allowed with a prominent warning that most commercial and OS-bundled typefaces forbid exactly this, and every generated header carries an attribution block naming the typeface, author, licence and origin.
- (JA) 掲載する Web フォントは、生成データのファームウェア埋め込みを許諾する SIL Open Font License 1.1 と Apache-2.0 の書体に限定した。ローカルファイルも使えるが、市販フォントや OS 同梱フォントの多くがまさにこれを禁じている旨を明確に警告する。生成されるヘッダには必ず書体名・作者・ライセンス・入手元の帰属ブロックを含める。
- (EN) Add transparent scenes (§8.16): a scene can be marked as an overlay, drawn on top of the screen already on the panel with no background of its own — a dialog with rounded corners or a shadow shows the running screen through it, and the screen below is never redrawn. Buffered builds push the frame through LGFXVirtualCanvas `renderTransparent()` with a project-wide color key (`project.transparentColor`, default `#002400` = `TFT_TRANSPARENT`); direct builds simply skip the background fill, which is equivalent. New example `DialogM5Unified`, and `Screen::supportsTransparentScenes()` reports whether the build honors it.
- (JA) 透過シーンを追加（§8.16）: シーンをオーバーレイ指定すると、自前の背景を持たず、パネルに出ている画面の上に重ねて描かれる。角丸や影のあるダイアログの外側からは動作中の画面が見え、下の画面は描き直されない。バッファ構成では LGFXVirtualCanvas の `renderTransparent()` にプロジェクト単位の抜け色（`project.transparentColor`、既定 `#002400` = `TFT_TRANSPARENT`）で転送し、直描画構成では背景を塗らないだけで等価になる。サンプル `DialogM5Unified` を追加。ビルドが対応しているかは `Screen::supportsTransparentScenes()` で分かる。
- (EN) Requires LGFXVirtualCanvas **1.4.0 or newer** for transparent scenes in a buffered build; an older version draws them as ordinary opaque screens and emits a `#warning`, so projects that do not use the feature keep building unchanged.
- (JA) バッファ構成の透過シーンには LGFXVirtualCanvas **1.4.0 以降**が必要。それより古い場合は通常の不透明画面として描き `#warning` を出すので、この機能を使わないプロジェクトは従来どおりビルドできる。
- (EN) `SceneDesc::transparent` and `Project::transparentColor` are appended to the descriptor and emitted **only when a scene uses them**, so a project without a transparent scene generates byte-identical output and its `.lgfxsb.json` is unchanged — `formatVersion` stays 1 (SPEC §9.2, Layer 1).
- (JA) `SceneDesc::transparent` と `Project::transparentColor` は記述子の末尾に追加し、**使うときだけ出力**する。透過シーンを持たないプロジェクトの生成物はバイト単位で同一、`.lgfxsb.json` も不変で、`formatVersion` は 1 のまま（SPEC §9.2 レイヤ1）。
