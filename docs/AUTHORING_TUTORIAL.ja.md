## 1. 画面の見かた

左端に**モードレール**（縦のアイコン列）があり、5 つのモードを切り替えます。

| モード | 役割 |
| --- | --- |
| **Design** | 画面（シーン）にパーツを配置する。ここが主戦場 |
| **Devices** | プロファイル（機種＝サイズ・回転）の追加と並べ替え |
| **Assets** | PNG / JPEG の取り込み |
| **Fonts** | 使うフォントを選び、プロファイル毎に有効化する |
| **Export** | `.h` の生成と保存 |

Design モードは**二軸**になっています。ここが最初の関門です。

```
        ┌──────── 上タブ = プロファイル（機種）────────┐
        │  Core  │  Stick  │  Cardputer  │            │
┌───────┼──────────────────────────────────────────┬──┐
│ 左    │                                          │右│
│ ペイン│              キャンバス                   │イ│
│ ＝    │        （選んだ シーン × プロファイル）    │ン│
│ シーン│                                          │ス│
│       │                                          │ペ│
│ Boot  │                                          │ク│
│ Main  │                                          │タ│
│ …     │                                          │  │
└───────┴──────────────────────────────────────────┴──┘
```

- **シーン** = 1 枚の画面（起動画面、メイン画面、設定画面…）
- **プロファイル** = 機種（Core 320×240、Stick 135×240…）
- キャンバスに出ているのは、選んでいる**シーン × プロファイル**の 1 組み合わせ

**重要**：パーツはシーンに属し、**全プロファイルで共有されます**。
座標だけがプロファイルごとに独立です。つまり「Core で `title` を追加すると、
Stick にも `title` が生えて、Stick 用の位置を別に決められる」という関係です。
パーツを消せば全プロファイルから消えます。

## 2. 新規プロジェクトをつくる

ツールバーの **新規** を押すとダイアログが出ます。

- **プロジェクト名** — 生成される C++ の名前空間になります。**C 識別子**にしてください
  （英数字と `_`、先頭は数字以外）。`MyScreen` と入れると `namespace MyScreen` と
  `MyScreen.h` になります。
- **最初のプロファイル — デバイス / サイズ** — 手元の機種を選びます。無ければ
  **カスタム…** で幅・高さを直接入れます。
- **最初のシーン** — シーン名。これも C 識別子です（`Main` など）。

**作成** で始まります。試しに触るだけなら、**デモ** ボタンでサンプルプロジェクトを
読み込むほうが早いです。

> 注意：**新規** は現在のプロジェクトを破棄します（確認が出ます）。

## 3. パーツを置く

左ペインでシーンを選び、パーツ一覧の **＋ 追加 ▾** から種別を選びます。

| 種別 | 用途 | 主なプロパティ |
| --- | --- | --- |
| **Rect** | 背景板、枠、バーの下地 | 幅・高さ・角丸・塗りつぶし・色 |
| **Line** | 罫線、区切り | X1,Y1 → X2,Y2・色 |
| **Circle** | インジケータ、点 | 半径・塗りつぶし・色 |
| **Text** | ラベル、値の表示 | 文字・基準点(datum)・文字サイズ（倍率）・フォント・色 |
| **Image** | ロゴ、アイコン | アセット選択（Assets モードで取り込んだもの） |

**パーツ ID** は生成コードのフィールド名になります。`battery` と名付ければ
`main.battery = "82%";` と書けるようになります。ここも C 識別子です。

### 操作

| 操作 | 効果 |
| --- | --- |
| クリック | 選択 |
| ドラッグ | 移動（座標はドラッグ中もライブ更新） |
| `↑` `↓` `←` `→` | 1px 移動 |
| `Ctrl`（`⌘`）+ 矢印 | 10px 移動 |
| `Shift` + 矢印 | リサイズ（1px） |
| `Ctrl` + `Shift` + 矢印 | リサイズ（10px） |
| `Delete` / `Backspace` | 削除 |
| ホイール | ズーム |
| 中ボタンドラッグ | パン |
| 空き領域をクリック | 選択解除 →**画面（シーン）自体のプロパティ**が出る |

### Text の datum（基準点）

Text は座標が**どこを指すか**を datum で決めます。ここを理解しておくと
機種間でレイアウトが崩れにくくなります。

- 左寄せのラベル → `top_left` 系。X が左端に固定される
- 中央に置きたいタイトル → `middle_center`。**X が中心**なので、文字数が変わっても
  中央のまま
- 右寄せの数値（電池残量など） → `top_right` 系。**右端が固定**されるので、
  `9%` と `100%` で右端が揃う

「値が伸び縮みするテキストは、揃えたい側を datum にする」と覚えてください。

### 何を静的パーツにして、何をコードで描くか

これが設計の分かれ目です。

- **値によらず常に出る下地**（枠、罫線、バーの外枠、0% 状態）→ **静的パーツ**
- **文字列だけ変わるもの** → **Text パーツ**。エディタで入れた文字は
  *デザイン時のプレースホルダ*で、実行時にシーン構造体で差し替えます
- **値で形が変わるもの**（バーの塗り、針、波形）→ **overlay でコードから描く**
  （[OverlayM5Unified](../examples/OverlayM5Unified/) 参照）

代表値のバーの塗りなどを静的パーツに焼き込まないでください。overlay が
上書きして二重に見えます。

## 4. フォントを採用する

既定は LovyanGFX の `Font0` で、小さくて素っ気ないフォントです。変えるには
**Fonts** モードで使うものを **採用** します。

カタログは**実描画の px 高さ**・文字種（ラテン / 数字 / 日本語 / 簡体字 / 繁体字 /
韓国語）・等幅か可変幅か・スタイル・ファミリで絞り込めます。タイルに出ているのは
**host で実際に描画したグリフ**なので、見た目そのままです。

採用したら、**プロファイル毎に有効化**します。ここが独特なので理由を書きます。

> フォントは**バイナリに焼き込まれ、Flash を消費します**。ラテン系は数 KB〜数十 KB
> ですが、**日本語・中国語・韓国語は数百 KB〜 MB 級**です。小さい画面の機種に
> 大きな CJK フォントを載せると、それだけで Flash が足りなくなります。
> そこで「このフォントは Core でだけ有効」という指定ができるようになっています。
> **フォント毎・プロファイル毎の正確な Flash 消費量**が表示されるので、
> 予算を見ながら決められます。

有効化したフォントは、Design の Text インスペクタの **フォント** ドロップダウンに
出てきます（そのプロファイルで有効なものだけ）。**フォントの選択もプロファイル毎**なので、
「Core では大きい和文、Stick では小さいラテン」といった使い分けができます。

## 5. 機種を増やす（プロファイル）

**Devices** モードで **＋ 追加 ▾**。解像度から選ぶか、カスタムで入れるか、
**現レイアウトをクローン**できます。

- **サイズ**（幅・高さ）と **デフォルト回転**を決めます。
- 回転は「**そのボードの標準の向きからの相対値**」です。`0` = 標準の向き。
  M5GFX のようにボード毎の標準回転がある環境でも、`0` と書けば正しい向きになります
  （ランタイムが `(標準回転 + プロファイル回転) % 4` で解決します）。
- **プロファイル順序**が実行時の解決順です。`Profile::Auto` は画面サイズが一致する
  **最初の**プロファイルを選び、一致が無ければ先頭にフォールバックします。
- 同じサイズの**既知ボード一覧**が参考表示されますが、**ボードの割り当てではありません**。
  解決はあくまでサイズで行われるので、同サイズの機種は同じプロファイルを共有します。

新しいプロファイルを足すと、既存の全シーン・全パーツがそこにも現れます。
あとは Design モードの上タブでそのプロファイルを選び、座標を詰めていくだけです。

## 6. 出力して実機に出す

**Export** モードへ。

**出力設定**：

- **プロジェクト名** — 名前空間とファイル名
- **対象フレームワーク** — M5Unified / M5GFX / LovyanGFX（サンプル `.ino` の
  include と初期化が変わります。描画 API は共通）
- **対象プロファイル** — 一部だけ出力できます。`enum class Profile` と
  データテーブルが選んだぶんに絞られ、載せない機種のレイアウトが Flash を食いません
- **バッファリング (LGFXVirtualCanvas)**（既定オン）— サンプル `.ino` に
  `#if __has_include` 付きの include を出します。**ちらつき対策なので基本はオンのまま**
- **AIレイアウトを埋め込む（コメント）**（既定オフ）— [9 章](#9-ai-にレイアウトを頼む)

**チェック** 欄に警告が出ていないか確認してください（例：透過シーンで抜け色と
同じ色のパーツ）。

**保存** すると 2 つのファイルが得られます。

- `MyScreen.h` — 生成物。**手で編集しない**
- `MyScreen_example.ino` — サンプルスケッチ。シーンツアーになっています

`.h` を `.ino` と同じフォルダに置き、次のように書きます。

```cpp
#include <M5Unified.h>

#if __has_include(<LGFXVirtualCanvas.h>)
#include <LGFXVirtualCanvas.h>          // ← 生成ヘッダより前！
#endif

#include <LGFXScreenBuilder.h>
#include "MyScreen.h"

using namespace MyScreen;
static Screen screen(M5.Display);

void setup() {
  M5.begin();
  screen.begin();

  Scene::Main main;
  main.title   = "Main";      // ← エディタで付けたパーツ ID がフィールド名
  main.battery = "82%";
  screen.show(main);
}

void loop() { M5.update(); }
```

必要なライブラリは、本ライブラリ（**LGFXScreenBuilder**）、ディスプレイライブラリ
（M5Unified / M5GFX / LovyanGFX）、そして任意で **LGFXVirtualCanvas**（ちらつき対策。
透過シーンを使うなら **1.4.0 以降**）です。

## 7. 作ったものを保存する

**2 種類のファイルがあり、役割が違います。**

| ファイル | 中身 | 用途 |
| --- | --- | --- |
| `*.lgfxsb.json` | プロジェクトそのもの | **これが正本。** 再編集はここから |
| `MyScreen.h` | 生成された C++ | 派生物。捨てても再出力できる |

ツールバーの **保存** / **開く** が `.lgfxsb.json` です。
**必ずこちらを保存してください。** `.h` からプロジェクトは復元できません
（AI レイアウト埋め込みを使えばレイアウトは復元できますが、正本ではありません）。

localStorage への自動保存もあり、ブラウザを閉じても再訪時に復元されますが、
**バックアップではありません**。キャッシュを消せば消えます。

## 8. 編集 → 出力 のループを速くする

File System Access API 対応ブラウザ（Chrome / Edge など）では、**その場上書き保存**が
使えます。

初回の **保存** でファイルを束縛すると、以降の Export は**同じファイルを黙って上書き**します。
つまり、

> ブラウザでレイアウトを直す → **保存** → Arduino IDE でビルド → 実機で確認 → 直す

を、ダウンロードや手動コピーなしで回せます。`.h` はプロジェクト外のパス
（スケッチのフォルダ）に束縛できるので、`.lgfxsb.json` は別の場所に置いたままで構いません。
**別名保存** もあります。非対応ブラウザでは従来どおりダウンロードになります。

## 9. AI にレイアウトを頼む

Design モードの **AI用JSONコピー** で、今の画面を**全プロファイルぶん**、
自己完結した JSON としてクリップボードにコピーできます。

これを [AI_LAYOUT_IO.md](AI_LAYOUT_IO.md)（AI 向けの契約書。**英語版が正本**）と
一緒に AI に渡し、「Stick 用の座標を詰めて」「余白を揃えて」などと頼みます。
返ってきた JSON を **AI結果を貼付** で取り込みます。同名シーンは上書き、
無ければ追加され、**適用前にプレビュー**が出て、**Undo も効きます**。

Export の **AIレイアウトを埋め込む（コメント）** をオンにすると、
全シーンの JSON が `.h` にコメントとして入ります。コンパイラが捨てるので
**バイナリには一切影響しません**。下流のツール（画面キャプチャギャラリーなど）が
`.lgfxsb.json` 無しでヘッダだけからレイアウトを読めるようになります。

## 10. よくある詰まりどころ

| 症状 | 原因 |
| --- | --- |
| プロジェクト名やパーツ名が弾かれる | C 識別子である必要があります（英数字と `_`、先頭は数字以外） |
| 片方のプロファイルで直したら他が崩れた | 座標はプロファイル毎に独立。**それぞれで**詰める必要があります |
| パーツを消したら別プロファイルからも消えた | 仕様です。パーツはシーンに属し、全プロファイルで共有されます |
| Text のフォントが選べない | そのプロファイルでフォントが有効化されていません（Fonts モード） |
| Flash が足りない | CJK フォントが原因のことがほとんど。プロファイル毎の有効化を見直す |
| 文字が中央からずれる | datum が意図と違います。伸縮するテキストは揃えたい側を datum に |
| 実機でレイアウトが選ばれない | `Profile::Auto` はサイズ完全一致で解決します。該当サイズのプロファイルがあるか確認 |
| 実機でちらつく | `screen.isBuffered()` を確認。`<LGFXVirtualCanvas.h>` が生成ヘッダより**前**にあるか |
| 透過シーンのパーツが消える | その色が抜け色（既定 `#002400`）と RGB565 で一致しています |
| 古い `.h` が新しいランタイムで壊れた | `.lgfxsb.json` から**再出力**してください。これが保証された回復手段です |
