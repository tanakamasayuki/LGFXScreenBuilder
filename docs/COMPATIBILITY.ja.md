# 互換性 FAQ — バージョンが噛み合わないとき

> English: [COMPATIBILITY.md](COMPATIBILITY.md)

「以前作った画面が新しいライブラリで動かない」「古い `.h` を渡されたがビルドが通らない」
といったときの短い案内です。詳細は [SPEC.ja.md](../SPEC.ja.md) §9.2 と §10.1 にあります。

## バージョンが付くものは 4 つ

| もの | どこで分かるか | 役割 |
| --- | --- | --- |
| **プロジェクトファイル** `*.lgfxsb.json` | ファイル内の `formatVersion` | **正本。** 画面の設計そのもの |
| **生成ヘッダ** `MyScreen.h` | 冒頭コメントの `formatVersion N` | 派生物。再出力できる |
| **本ライブラリ** | [library.properties](../library.properties) | `.h` を解釈して描く実行時エンジン |
| **LGFXVirtualCanvas**（任意） | `LGFXVIRTUALCANVAS_VERSION_*` マクロ | バッファ描画と透過転送 |

## 保証は 2 段階で、強さが違う

- **プロジェクトファイル ⇄ オーサリングツール — 強く保証する。**
  新しいツールは古い `.lgfxsb.json` を読めます。ここが真実の源です。
- **生成ヘッダ ⇄ ランタイム — ベストエフォート。**
  新しいエンジンは原則として過去のツール版が生成した `.h` を読めますが、
  こちらは意図的に弱い保証です。

**だから、保証された回復手段は「プロジェクトファイルからの再出力」ひとつです。**
`.lgfxsb.json` さえ手元にあれば、何が起きても最新のツールで開いて Export し直せば直ります。

## なぜ古い `.h` がそのままビルドできるのか

記述子は**位置指定の集成体**として初期化されます。新しいフィールドは必ず**末尾に追加**され、
ライブラリ側の構造体が**旧挙動と同じ既定値**を持ちます。集成体初期化は
メンバ数より初期化子が少なくても valid なので、**新フィールドを知らない古い `.h` も
そのままコンパイルでき、省略されたフィールドは既定値になります。**

透過シーン（§8.16）がその実例です。`SceneDesc::transparent` と
`Project::transparentColor` は末尾に足され、**実際に使うシーンがあるときだけ出力される**ので、
透過シーンを持たないプロジェクトの生成物は機能追加前とバイト単位で同一です。
これが `formatVersion` を上げずに済んだ理由です。

逆に、フィールドの**並べ替え・削除・中間挿入**は位置がずれる破壊的変更なので、
そのときだけデータ契約版を上げて再出力を案内します。

## 症状別

| 症状 | 対処 |
| --- | --- |
| 古い `.h` がコンパイルエラー | `.lgfxsb.json` を最新ツールで開いて**再出力**。これが正規の手段 |
| `.lgfxsb.json` が無く `.h` しか無い | Export 時に *AIレイアウトを埋め込む* が ON なら、ヘッダ末尾のコメントブロックからレイアウトを復元できます（§10.2）。OFF だった場合、レイアウトは失われています |
| `#warning "LGFXVirtualCanvas < 1.4.0..."` | 透過シーンにはバッファ描画で 1.4.0 以降が必要。更新するか、そのまま不透明描画で使う |
| 透過シーンが不透明に描かれる | 上と同じ。`screen.supportsTransparentScenes()` が false になっているはず |
| ちらつく／`isBuffered()` が false | バージョン問題ではなく **include 順**です。`<LGFXVirtualCanvas.h>` を生成ヘッダより前に |
| 複数 `.cpp` でリンクがおかしい | 翻訳単位ごとに include の有無が食い違うと `Canvas` の型が変わり ODR 違反になります。ビルドフラグでプロジェクト全体にモードを固定してください |
| 生成ヘッダを手で直したら壊れた | `.h` は手編集しない前提です。編集はツール側で行い、再出力してください |

## 実践的な習慣

- **`.lgfxsb.json` をリポジトリにコミットする。** `.h` だけを版管理すると、
  上の回復手段が使えなくなります。
- **`.h` は生成物として扱う。** 手で直さない。冒頭に
  `// Generated by LGFXScreenBuilder (formatVersion N). Do not edit by hand.` と入っています。
- **再出力は安価です。** このリポジトリ自身、全 example のヘッダを
  `node tools/gen-fixtures.mjs --write` の 1 コマンドで作り直し、
  `--check` が CI で陳腐化を検出しています。同じことを自分のプロジェクトでもできます。
